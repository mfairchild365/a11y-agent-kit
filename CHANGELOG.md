# Changelog

## Unreleased

- New `scripts/tree-pass.mjs`: a fixed pass over the browser's accessibility tree. It reports candidates (not verdicts) for unnamed controls, visible text missing from the name (2.5.3), repeated link and control names that their surroundings don't explain, focusable controls inside `aria-hidden`, duplicate or missing landmarks, and heading outline gaps. It covers same-origin frames and open shadow roots, stops with a recorded reason (`complete`, `node-cap`, `load-timeout`), and has 49 fixtures behind it.
- New `scripts/keyboard-walk.mjs`: presses Tab through the page and reports unnamed controls that take focus, tabbable controls focus never reaches, positive `tabindex`, and possible keyboard traps (a repeated stop, or Tab cancelled by a script twice running). It is bounded by stop and time caps, tells a single-tab-stop wrap from a trap, treats a modal's focus loop as expected, and reports a trap as a candidate to confirm by hand. 33 fixtures.
- Audit reports: every full card has a **Guard** (`automatable` or `manual`: the smallest check that fails now and passes after the fix), the Summary and digest have a **Triage** line (Fix now, Ticket or Investigate for every numbered issue) and a Guards count, and a re-check adds a **Since the last audit** section. New `scripts/compare-reports.mjs` compares two reports by element and success criterion and lists what is resolved, still open and new (28 fixtures).
- Fixing from a report: write each automatable Guard as a test first, watch it fail, fix, watch it pass, and do the manual ones by hand; a project that opted out gets no tests and is told why. New `testing.md` sections: "Tree pass and keyboard walk", "Reaching signed-in and deep states" (use the project's own fixtures, never write credentials into a report), "Project conventions" (read the project's own accessibility notes first) and "Turning a reported issue into a fix with a test".
- Calibration and procedures (proposed, not yet confirmed by the maintainer, and marked so in the text): repeated link names fail 2.4.4 only when nothing around them tells them apart; repeated control names don't fail 4.1.2 and are a Best practice; a positive `tabindex` and a missing level 1 heading are Best practices; script output is evidence, never a finding on its own (section E); and a component library defect says where the fix belongs, with consumer workarounds labelled temporary.
- Dev tooling (nothing changes for users of the skill or agent): all repo tooling is now Node. `scripts/sync_plugin.py` and the eval scripts (`run_cli_eval`, `trigger_check`, `grade_axe`, `grade_upstream`, `strict_summary`) are ported to `.mjs` with tests, including end-to-end runs of the two `claude` launchers against a fake CLI; `build_review.py` and `run_trigger_eval.py` stay Python because they patch skill-creator's own modules. Also new: a fixture runner and rules for deterministic checks (`evals/check_fixtures/`, every check needs positive, negative, edge and termination fixtures with answer keys, and the runner has its own tests), and a gate, run by `sync_plugin.mjs --check`, that fails when a tracked file names a company, brand or product on a hashed blocklist.

- New `components/toast.md`: toast / snackbar guidance built from Scott O'Hara's and Adrian Roselli's writing. Decide whether a toast is needed, prefer inline or static messages, keep the toast supplementary, give users a history instead of relying on timers, keep actions out of the live region, and state the message type in text. Audit calibration: an interactive control other than Dismiss inside a live-region toast is a Best practice. The message history is a heading and a list, not a `role="log"` live region (announcing every entry is noise), and a toast title is a heading. Also new: avoid naming a section that already has a heading, and avoid changing a focused button's inner text to show state. Both are Best practices in the audit (calibration D), and the page-layout example no longer names its section.
- Calibration from a snackbar audit: a non-text contrast failure (1.4.11) is Moderate at minimum, never Minor; a status icon that carries the message type is not decorative (1.1.1) unless the text states the type; an auto-dismissing message (2.2.1) needs more than pause on hover or focus: actionable or important messages should not auto-dismiss, and dismissed messages should be re-openable. New procedure entries for 1.1.1 and 2.2.1, and a snackbar in the audit fixture (3 seeds, 2 decoys).
- Status messages (4.1.3): new `scripts/live-region-probe.mjs` records live-region changes that are added and removed within milliseconds, with the region, whether it existed and is exposed to assistive technology, the dwell, and whether focus moved, including inside shadow roots. The procedure classes results and sends anything the browser can't settle (a transient message, a region inserted with its text) to Needs verification, since it can't show what a screen reader speaks.
- Audit procedures: new `references/audit-procedures.md` with test steps, failure conditions and "does not fail" boundaries for 15 error-prone criteria (1.1.1, 1.3.1, 1.4.3, 1.4.10, 1.4.11, 1.4.12, 1.4.13, 2.1.1, 2.2.1, 2.4.7, 2.4.11, 2.5.3, 2.5.8, 4.1.2, 4.1.3), each drafted from its W3C Understanding page and checked line by line against the page text. They are not the audit's scope: the reviewer still audits every applicable A and AA criterion.
- Reflow (1.4.10): the 256px height test applies only to content that scrolls horizontally (vertical text), and a single overflowing line is a Best practice, not a failure.
- Calibration: `list-style: none` without `role="list"` is not a WCAG failure and is not logged.
- Calibration: 1.4.11 is Critical only when the failing element is required to identify the control or its state. A border around a control with visible text, and a panel edge, are not failures (Best practice at most). Text contrast (1.4.3) stays Critical.
- Audit delivery: the reviewer returns a short digest (Fix first, counts, one line per issue, a link) and writes the full report to `report.md`. A new dependency-free `scripts/render-report.mjs` renders `report.html` (images inlined, Evidence folded, table of contents, light and dark) and can open it; the agent shows or opens it for the user and never publishes it to a hosted service unasked. Report noise is cut: no text outside the template's sections, length caps, no index table, and documentation or test gaps are not findings.
- Anchors are floors that can't be lowered. Process safety: the reviewer stops only processes it started.
- Audit calibration: new `references/audit-calibration.md` with severity anchors (keyboard-inoperable and contrast failures are Critical, and so on), a rule to split a defect that fails two criteria into two issues when the barriers differ, and a don't-log list. Best practices are now labelled "Best practice" in their own table instead of being rated Minor.
- Audit report: less noise. It opens with a two-sentence verdict and a **Fix first** list, and each issue has a one-line headline with severity, SC, instances and confidence, with the evidence folded below. Minor issues become table rows, Low-confidence findings move to **Needs verification**, and `report.html` is the primary view with collapsible evidence.
- Audit report: findings are grouped by offending element, then by WCAG success criterion, most severe first. Each issue maps to one SC, instances of the same element and failure are merged into one issue, and the summary has an issue index table.
- `accessibility-reviewer` agent: always runs a real-browser check and axe-core when one is reachable (keyboard, hover/focus content, 320px reflow, zoom, reduced motion), and reports with the new `references/audit-report.template.md`. Each finding has a title, summary, severity and why, repro steps, observed, expected, fix, elements, and confidence; the report opens with an audit summary. Severity definitions are tightened. The agent saves the full report to a temp file and tells the calling agent to relay it verbatim, so a delegating agent no longer condenses it. Every finding with a rendered element carries a screenshot with that element outlined, including non-visual issues, with text evidence beside it. Screenshots are embedded in their finding and numbered by finding, and the agent also writes a self-contained `report.html` with the images inlined.
- Forms: character count / limit guidance (describe the current count and limit on focus, announce only near and at the limit).
- Status messages: WCAG definition, removal as a status message, brief loaders still need announcing, a single page announcer utility, and aggregating announcements for many concurrent loaders.
- New `tooltip` component: tooltips vs. toggletips, no `title` tooltips, toggletip content placed after its trigger.

- Added the `accessibility-reviewer` agent. It is a read-only audit that runs the project's accessibility tests or axe-core, and reports findings by severity.
- Includes the `building-accessible-ui` skill.
